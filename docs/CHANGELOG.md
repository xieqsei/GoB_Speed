## 4.5.3-Speed — 2026-11-23

### 新增

- **面板子面板「临时数据管理」**（3D 视图侧栏 `GoB` 面板下，默认折叠）
  - 统计两个中转目录的占用与文件数：`交换目录`（GoZProjects/Default）与 `GoZBrush`
  - 显示每个目录中「可清理」的大小，并可直接在资源管理器中打开
  - 清理白名单：`.GoZ` / `.ztl` / `.ztn` / `.bmp`；GoZ 配置、`GoZ_Config.bak`、`GoZ*.exe` 一律不动
  - 清理前弹出确认框（文件数 + 释放空间），执行后自动重新统计
  - 支持「保留时长」与「清理范围」两项设置；最近修改过的文件默认跳过
  - 启动后 1 秒自动统计一次（只读，不删除），面板打开即可看到数据
- **S导入自动找回细分**：面板勾选「找回细分」后，导入完成即对每个对象自动执行
  - 无 Multires 修改器则新建一个（GoZ 覆盖进来的高模才有载体）
  - 在空 Multires 上执行「重建细分」，依据当前高模反推出尽可能多的较低层级
  - 把视图层级设为 2，避免打开视口时直接求值最高级导致卡顿
  - 已有细分级别的对象跳过重建，只降层级
  - 另有独立命令 `scene.gob_s_recover_multires`，可对选中对象事后补做
  - 实测 40,401 顶点网格：未勾选时无修改器；勾选后得到 `total_levels=3 / levels=2`
- 首选项顶部显示分支版本号 `GoB 4.5.3-Speed`
- `docs/` 文档目录，集中存放所有更新日志与专项说明

### 性能：S导入 vs 原版导入

同环境（Blender 5.2.1 LTS / Windows / 无界面 / 沙箱 GoZ 目录）、同一批 `.GoZ` 各读一次，取首次导入的真实耗时：

| 场景 | 数据量 | S导入 | 原版导入 | 相对 | 绝对节省 |
|---|---|---|---|---|---|
| 单对象 18.1 万顶点 | 10.7 MB | 0.17 s | 0.22 s | 1.3× | 0.05 s |
| 单对象 72.4 万顶点 | 42.7 MB | 0.67 s | 0.95 s | 1.4× | 0.28 s |
| 单对象 144 万顶点 | 85.2 MB | 1.51 s | 2.09 s | 1.4× | 0.58 s |
| 4 个对象 × 144 万顶点 | 340.7 MB | 6.00 s | 8.04 s | 1.34× | 2.04 s |

- 绝对节省随数据量线性放大：18 万顶点省 0.05 s，340 MB 批量省 2.04 s，批量大网格体感最明显
- 相对倍数稳定在 1.3–1.4×：上游 4.5.3 把原版导入器从 `from_pydata` + `struct.unpack` 逐元素解析改为 `foreach_set` 批量写入，4.2.3 时代那种数量级差距已被追平
- S导入仍在大文件上占优（向量化解析 + 批量写入），属于"每次省一点、文件越大省得越多"


### 合并上游（4.2.3 → 4.5.3）

- 取上游 `v4_5_3` 源码与本分支做三方合并，逐文件解决冲突
- 上游带来的主要变化（详见下方上游条目）：导入器全面重构（按块长度读取、损坏数据可恢复）、
  UV/顶点/面集等大网格性能优化、轴重映射、蒙版导出选项、Windows/macOS 双路径、
  顶点组在拓扑一致时保留、ZBrush 细分级别回传修复

### 分支改动在上游代码上的落位

| 文件 | 分支改动 | 处理方式 |
|---|---|---|
| `gob_import.py` | 中文对象名 | 上游仍用 `string.printable` 过滤，改为保留可打印字符（含中文） |
| `gob_import.py` | UV 按面顶点序列配对写入 | 上游仍按面序顺序写；新增 `_pair_uvs_to_mesh()`，面数不一致时启用配对，避免被 `validate()` 删面后整体错位 |
| `gob_import.py` | 多边形组越界保护 | 上游已用 `min(cnt, payload, len(polygons))` 截断，无需再改 |
| `gob_export.py` | 中文名按 UTF-8 字节写长度域 | 上游改为「ASCII 编码失败就重命名对象」；分支保留原始名称，不重命名用户对象 |
| `gob_export.py` | 曲线等非网格对象转换后无面时提示 | 上游只对 `MESH` 分支提示；补在曲面/曲线分支并清理临时网格 |
| `gob_export.py` | 项目路径结尾分隔符 | 新增 `_normalized_project_path()`，手填路径没有结尾斜杠时不再拼出无效路径 |
| `gob_s_import.py` | S导入（本地独有模块） | 保留；路径刷新改用上游 `paths.set_goz_path_from_preferences()` |
| `ui.py` | 侧栏 `GoB` 面板 | 保留；同时恢复上游顶栏按钮，两者并存 |
| `geometry.py` | 曲线可导出 | 保留分支行为（转换后无面时提示），不采用上游「必须有倒角/挤出才可导出」 |
| `preferences.py` | 全中文界面 | 以上游 4.5.3 的新结构为基，重新汉化全部选项与说明 |

### 版本号规则

- `blender_manifest.toml` 的 `version` 只允许纯 `X.Y.Z`（扩展校验要求），因此固定为基线上游版本 `4.5.3`
- 分支标识写在 `__init__.py` 的 `BRANCH_TAG = "Speed"` 与 `VERSION_STRING = "4.5.3-Speed"`
- 插件名、manifest 名称、首选项标题、`utils.gob_version()`（写入 GoZ 变量文件）统一带分支标识
- 后续升级：改 `VERSION` 与 manifest 的 `version` 为新的上游版本号，`BRANCH_TAG` 不变

### 已知差异

- 导出**不再**重命名含非 ASCII 字符的对象（上游 4.4.1 起的做法）。分支按 UTF-8 写入名称块，
  已实测 Blender → ZBrush 2026 → Blender 往返正常；若个别 ZBrush 版本对名称块挑剔，可手动改英文名后再导出
- 顶栏 Import/Export 按钮与侧栏面板并存，两者调用同一批操作符

## 4.2.3-Speed — 2026-11-02

- 新增 **S导入**（`gob_s_import.py`）：一次性读入 `.GoZ` 并用 numpy 向量化解析，
  按块长度推导载荷，不再信任计数域，兼容 ZBrush 2026 的 POLYPAINT 计数宽度变化
- 修复 S导入在含退化面网格上 `internal error setting the array`（校验时机后移 + 长度对齐）
- 修复普通导入 UV 错位（改为按面顶点序列配对写入），内部边 UV 一致率 6% → 98.8%
- 修复中文对象名被截断（导入 ×2 + 导出 ×1）
- 多边形组写入越界保护
- 详细说明：`GoZ导入修复更新说明.md`

# 上游主线（摘录自 GitHub Releases）

## v4.5.3 — 2026-09-16

- 含额外数据的 `.GoZ` 不再导致后续纹理等数据被跳过
- 纹理缺失或损坏时仍完成网格导入，并给出警告
- 不完整/畸形 GoZ 数据的处理更安全
- 清理扩展打包流程，移除过时的构建脚本

## v4.5.2 — 2026-09-11

- 回传网格时保留 ZBrush 细分级别（即使子工具不在最低细分级别）
- 修复「匹配对象存在于文件中但不在当前视图层」时的重新导入
- 新增 Windows / macOS 两套独立路径设置

## v4.5.1 — 2026-08-30

- 高面数网格的导入/导出性能显著提升，内存占用下降
- UV、多边形绘制、蒙版、面集、多边形组处理更快

## v4.5.0 — 2026-08-20

- 拓扑完全一致时保留骨骼顶点组，拓扑变化时仍走安全重建
- 轴重映射导入导出互为逆运算，翻转轴时保持多对象相对位置
- 修正手动 / Blender 单位 / ZBrush 单位缩放，拒绝 0 缩放
- 改进原生 `.sculpt_face_set` 兼容性，面集经过修改器与三角化后仍保留
- ZBrush 只提供部分 UV 时导入可用部分，并报告不一致，后续块仍对齐
- 多边形绘制读取更稳健

## v4.4.2 — 2026-06-25

- 多边形组校验更稳健，避免部分导入报错
- 旧版 Blender 的面集导出修复

## v4.4.1 — 2026-06-03

- 导出时移除非 ASCII 字符（上游认为 ZBrush 无法传递）—— 分支不采用此策略

## v4.4.0 — 2026-06-03

- 新增轴重映射：任意轴可映射到任意轴，并可单独翻转每个轴

## v4.3.1 — 2026-05-20
